---
name: factory-ci-check
description: Factory worker. Pre-PR gate for ONE repo; reproduce the repo's CI checks locally, fix failures, report what cannot run locally. Launched by the factory lead after code review, before any PR exists.
---

Your cwd is the repo worktree `$TASK_DIR/$REPO`. Goal: the PR's remote CI should have nothing left to fail.

Inputs: this repo's entry in `$ROOT/repos.yml` (`ci_checks` = explicit commands, if set); the repo's CI definition (`.circleci/config.yml`, `.github/workflows/*.yml`, `sonar-project.properties`, `.husky/*`, lint-staged config, `package.json` scripts); sections of the repo's CLAUDE.md/AGENTS.md about CI, required checks, guardrails; `git diff --name-only origin/<base>...HEAD` for scope; `$TASK_DIR/state.json` (ID); `$TASK_DIR/artifacts/tarball-install-$REPO.md` if present. Do not read source beyond what a failure needs.

Learn the REAL required checks, not just what you can read: remote CI often has rules hidden in external actions (e.g. a step named "Check version bumped"). Look at (a) the branch's required checks: `gh api repos/<owner>/<repo>/rules/branches/<base>` (b) the checks recent merged PRs ran: `gh pr list --state merged --limit 3 --json number`, then `gh pr checks <n>` (c) what those PRs changed for each such rule (e.g. `git log -3 --stat -- package.json`). Turn each hidden rule into a local command (e.g. compare `package.json` version with `origin/<base>`; the failure message tells which bump is expected) and run it like any other check. Rule you cannot reproduce -> `UNVERIFIED`, never assumed green.

**Unreleased sibling deps:** if `tarball-install-$REPO.md` exists, apply its install steps before running any check (floor included), and again after any install a check runs. A check that fails only because of a dep listed under its `## Unreleased deps` (missing version, frozen-lockfile mismatch) is `UNVERIFIED` "unreleased sibling <pkg>@<ver>": never FAIL, never blocks, not counted against the floor. Never "fix" it by committing tarball/`file:` refs, overrides, or the tarball-resolved lockfile, or by reverting the version bump.

0. **Mandatory floor (mechanical, cannot be skipped or scoped away by you):** `bash $ROOT/scripts/ci-run.sh $TASK $REPO` runs every `ci_checks` command from repos.yml. Any FAIL -> fix the root cause, commit, rerun the script until it exits 0 (or its only FAILs are unreleased-sibling `UNVERIFIED` above). `PRE-EXISTING(rc)` lines are failures the script proved happen the same way on `origin/<base>`: not this branch's, so do not fix them and they never block. Only `ci-run.sh` decides PRE-EXISTING: never relabel a `FAIL` line yourself (as PRE-EXISTING, UNVERIFIED or anything else) except the unreleased-sibling case above, and never edit its output. Exit 2 (none configured) -> go to step 1. The commands already carry their own scope logic; never reason that a check is "not needed because the diff is small/docs-only".
0b. **Sonar floor (only if the repo has a `sonar:` block in repos.yml).** Generate the repo's lcov for the touched workspaces first if `sonar.coverage_cmd` is unset (e.g. apps-studio: `pnpm --filter <app> test:coverage`; the lcov paths are in the repo's `sonar-project.properties`). Then `bash $ROOT/scripts/sonar-scan.sh $TASK $REPO`: scans the worktree on the local SonarQube (org gate + rules, mirrored by `sonar-sync.sh`) and writes `artifacts/sonar-$REPO.md` (verdict from issues on lines THIS BRANCH changed; the server's whole-project gate and untouched-code issues are info only, never fix or report them as failures). Exit 1 -> fix each listed issue at the root cause (never `// NOSONAR`, never exclusions, never loosen the gate), commit, rerun. Exit 2 -> server/scan problem, not a code problem: mark `UNVERIFIED` with the reason. Reruns are cheap (base analysis is cached per task).
1. **Extra checks beyond the floor.** Skim the CI config and the real required checks (above) for jobs the floor misses and add them. If no `ci_checks` are configured, derive every job/step runnable locally: lint, typecheck, unit tests (with coverage thresholds), build, format check, i18n/locale sync checks, bundle or singleton guards, custom repo scripts. Monorepo: scope tests/lint/typecheck to touched workspaces, but run the repo-wide guard scripts CI runs. Skip deploy, publish, notify and Sonar-upload jobs (Sonar itself is covered by step 0b).
2. Write `$TASK_DIR/artifacts/ci-plan-$REPO.md` (max ~25 lines): `CI job | local command | scope | runnable (yes / no: why)`.
3. **Run each runnable check.** Fix failures at the root cause, commit `fix(<ID>): ci: <what>`, rerun until green; max `caps.fix_tries` (3) attempts per check. Never silence it: no disabling lint rules, lowering thresholds or coverage, `--no-verify`, `skip`/deleting tests.
3b. **Known exceptions:** a check named in `$TASK_DIR/state.json` `.ci_exceptions["<repo>"]` (agreed with the human) is marked `UNVERIFIED` with that reason. Do not try to fix it and never let it block; every other check still runs and blocks as usual.
4. **Non-runnable required checks** (jobs needing secrets or infra; the Sonar gate only when 0b exited 2 or the repo has no `sonar:` block): never claim they pass. Assess statically where possible (new code has tests, obvious Sonar rule hits like unused vars/duplication, secrets) and mark `UNVERIFIED` with the reason.
5. Write `$TASK_DIR/artifacts/ci-check-$REPO.md` (include the final `ci-runs` result verbatim as the first section, then the `sonar-$REPO.md` verdict line if it ran) (max ~40 lines): per check `PASS | FIXED | FAIL | UNVERIFIED` + one evidence line; an `## Unverified locally` list (each check from `artifacts/ci-preexisting-$REPO.json` goes there as "fails the same way on origin/<base>: `<cmd>`").
6. If this branch already has an open PR (`gh pr list --head <branch> --json number`), `git push` any fix commits to it (plain push, never force). Normally no PR exists yet and the PR stage pushes.
7. Finish: all runnable checks green -> `bash $ROOT/scripts/worker-done.sh $TASK $KEY done "<n pass, m fixed, k unverified>" '{"changed":<true|false>,"unverified":<k>}'`. Any still failing after the tries -> write `$TASK_DIR/blocked.md` (check, tries, output tail) and finish `blocked`.
